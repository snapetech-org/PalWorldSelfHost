Protected offline mutation
Save repair & identity migration
No offline repair plan has been reviewed.
The plan binds every save byte, installed build, schema and parser hash. Apply requires zero players, a verified protected backup and stopped-world staging; failed startup restores the untouched world automatically. Existing-identity replacement requires a disposable joined target. Cross-world transfer reads a sibling source world without changing it and replaces a disposable joined target with the source player's progression, inventory, party and Palbox while retaining the target guild. Bounded offline editors update exact inventory/currency slots, player level/experience, and owned-Pal nickname, level, rank, talents and passives. Duplicate cleanup keeps only the player-save and guild-backed instance. Save-graph cleanup repairs dangling character/item slots and removes globally unreferenced records. Inactive cleanup removes profiles, owned Pals, empty guilds and newly orphaned containers. When an empty guild owns bases, it also deletes a closed, reverse-reference-verified graph of bases, workers, work records, connected structures, item containers, dynamic items and spawners; retained members or shared/unknown ownership fail closed.

Installed mod configuration
PalDefender settings & Lua state

      
Loader lifecycle
PalDefender and UE4SS DLLs require the opt-in Windows-under-Wine runtime. Install, update, remove and rollback use reviewed release hashes, require a stopped world and preserve saves, generated PalDefender data, UE4SS settings and Lua mods.

      
Only documented scalar PalDefender keys are shown. IP lists, bans, filters, tokens and unknown future keys never enter this form and are preserved value-for-value during a merge. Apply is bound to the reviewed file hash, takes a private snapshot and never restarts the world automatically.
